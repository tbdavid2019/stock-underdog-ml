# 模擬交易基礎元件（開發中）

此資料夾的元件目前用於重現成本、下單風控與帳本行為；完整的歷史回測與每日模擬執行器仍待接通。這些結果均屬模擬，不連接券商，也不代表真實成交。

## 成交與風控

`backtest.simulation.CostSchedule` 要求呼叫方明確提供市場、商品、生效日期、費率、最低手續費、滑價與交易數量單位。`execute_open` 只接受訊號產生後的開盤價，依決策前已知的最近 20 筆歷史開盤量及日成交量估算上限；至少要 10 筆有效資料。上限取開盤量中位數的 1% 與平均日量的 1% 之較小者。未成交餘量當日取消，成本按實際成交量計算。缺少開盤量或無法確認資料時間的當日觀測，不推算成交。

`backtest.risk.assess_order` 根據外部提供的帳戶快照檢查現金、單股、產業、相關群組、總曝險、日均成交量與回撤。買入需要新鮮的資料與分類；賣出以實際持有股數為上限，允許在資料過期時降低部位。風控回傳量、原因、限制與政策版本，資料快照應由呼叫方在決策時固定。

費率因市場、商品、期間與券商而不同。台灣證交所的[交易制度說明](https://www.twse.com.tw/en/products/system/trading.html)列出一般股票賣出證券交易稅與手續費標準；[SEC 2026 年度費率公告](https://www.sec.gov/rules-regulations/fee-rate-advisories/2026-2)說明美國 Section 31 費率自 2026-04-04 起變動。這些公告不足以推定使用者的券商手續費或完整歷史稅率。當前程式要求使用者提供已確認版本，沒有自動預設或宣稱完整涵蓋台、美、日費用。

## 帳本

`PaperLedger` 將每個帳戶限定市場與幣別，在 DuckDB 交易中一併保存訂單、已成交數量、手續費、現金、持倉與已實現損益。同一訂單或公司事件以固定 ID 重試時保持冪等；部分成交後未成交數量記為 cancelled。`apply_corporate_action` 支援拆股調整與每股現金股利；輸入價格應為未還原價，以避免股利重複計入。

呼叫方必須先供應與訂單匹配的風控結果。**風控快照與記帳尚未包成同一筆資料庫交易**；完整模擬執行器、上市／停牌與漲跌停資料、即時資料新鮮度、日終估值及對帳、回測績效與管理 API 仍待完成，因此本文件描述元件的限制，不將其視為已可投入正式排程。
